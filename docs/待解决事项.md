## 对标校验口径

- [Freqtrade dry-run/production 文档](https://docs.freqtrade.io/en/latest/configuration/) 将 dry-run 定义为模拟钱包和模拟订单，production 才执行真实订单；因此本项目的 paper/mock 通过不能等价于 live 可扩容。
- [CCXT sandbox/testnet 文档](https://github.com/ccxt/ccxt/wiki/manual#testnets-and-sandbox-environments) 要求 sandbox/testnet 在创建 exchange 后、任何调用前启用，且 sandbox key 与 production key 不可混用；因此 OKX testnet 必须单独留验收记录。
- [Hummingbot connector 文档](https://hummingbot.org/docs/) 强调 connector 标准化交易逻辑和订单类型；因此本项目 `execution_result` 不能只在 open 路径标准化，close/risk/sync/external close 也应收敛到同一契约。
