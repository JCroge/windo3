## 4. 最终阻塞项

### P0-1 Probe slot / pending 记账未闭环，仍可能违反“同时最多 1 个 probe_short”

位置：

- `agents/trading/judge.py:1745-1759`
- `agents/trading/judge.py:1314-1347`
- `agents/trading/judge.py:1393-1414`
- `utils/candidate_ranker.py:45-124`

当前 `_can_route_probe_short()` 只检查 `_probe_short_active`，没有检查：

- `_pending_open_slots` 中是否已有 `probe_short`
- `_pending_open_symbols` 中是否已有 pending probe
- 当前 ranking buffer 内是否已有另一个 probe candidate
- final slot gate 中的 `slot_type == "probe_short"` cap

同时，`CandidateRanker.rank_and_select()` 只区分 normal 和 low_rr：

```python
normal_scored = [not is_low_rr]
low_rr_scored = [is_low_rr]
```

`probe_short` 会被归入 normal candidate，不会按 `probe_short_max_concurrent=1` 单独限流。

可发生的场景：

1. 同一个 ranking 窗口里两个 symbol 都满足 `degrade_to_probe`。
2. 两者调用 `_can_route_probe_short()` 时 `_probe_short_active is None`，都被 route 成 `slot_type=probe_short`。
3. Ranker 把它们当 normal candidate，只要 main slot 还有空间，就可能同时 selected。
4. `_flush_ranked_candidates()` 把两个都加入 `_pending_open_slots`，此时已经出现两个 pending probe。

另一个场景：

1. `RANKING_ENABLED=false`。
2. 第一个 probe open decision 已 publish，但尚未收到 execution_result。
3. 第二个 probe 信号到来时 `_probe_short_active` 仍是 None。
4. 第二个 probe 也可 publish。

反向问题也存在：

- 当 main slot 已满但 probe slot 空时，预闸门允许继续构建 probe；
- 但 Ranker 没有 `available_probe` 逻辑，probe 被当 normal，`available_main=0` 时会被 reject；
- 这会削弱 PRD 想保留的 bullish 顶部早期反转探测通道。

验收影响：

- AC-SHORT-03 未完全通过。
- AC-SHORT-04 未完全通过。
- AC-RR/slot 体系在 probe 维度仍不一致。

建议修复：

1. `_can_route_probe_short()` 增加 pending probe 检查：
   ```python
   any(slot == "probe_short" for slot in self._pending_open_slots.values())
   ```
2. plan 确定后 final slot gate 增加 `slot_type == "probe_short"` 分支。
3. Ranker 支持 `probe_short` 独立容量：
   - `available_probe = probe_cap - probe_used`
   - probe candidates 单独排序，最多取 1 个。
4. ranking buffer 内 route probe 时可先做本轮临时 reservation，避免同批多个 probe 都通过 `_can_route_probe_short()`。
5. 补测试：
   - 同一 ranking window 两个 probe 只选一个；
   - 已有 pending probe 时第二个 rejected；
   - main 满但 probe slot 空时，probe 可进入 probe slot；
   - ranking disabled 时 pending probe 仍阻止第二个 probe。

## 5. 高优先级残余问题

### P1-1 Ledger 支持 attribution，但很多 rejected plan 实际仍写不进去

位置：

- `agents/trading/judge.py:1016-1018`
- `agents/trading/judge.py:1053-1074`

- `agents/trading/judge.py:1834-1845`
- `utils/counterfactual_ledger.py:60-68`

`CounterfactualLedger.record_rejection()` 已支持 `attribution`，但 Judge 的 `_record_rejected_plan()` 只读取：

```python
attribution = plan.get("attribution") or {}
```

问题是大量 reject 发生在 `_build_attribution()` 之前：

- quality gate reject
- short guard reject
- degrade_to_probe unavailable reject
- dynamic R:R reject
- 15m blocked reject
- deferred regime reject

这些路径的 trade_decision 有些会手动带 `_rejection_attribution()`，但 ledger 调用发生时 plan 还没有 `attribution`。结果是 ledger 事件仍可能缺少：

- `raw_regime`
- `regime_confidence`
- `rr_policy`
- `slot_type`
- `blocked_by`
- `is_probe`
- `is_low_rr`

此外 short guard/degrade rejected 的 trade_decision 仍手写 attribution，只包含 `entry_regime` 和 `blocked_by`，ranked_out hold 仍没有 attribution。

建议修复：

- `_record_rejected_plan()` 增加 `attribution: dict = None` 参数。
- 各 reject 路径调用时传入 `_rejection_attribution(action, plan, reason)`。
- short guard/degrade/ranked_out/deferred `_publish_hold()` 统一带完整 attribution。
- 补 `test_counterfactual_ledger.py` 或新增 Judge 测试，验证 ledger record 真实包含 `raw_regime/rr_policy/slot_type/blocked_by`。

### P1-2 Probe 市场级触发条件仍不是 PRD 严格版本

位置：

- `utils/market_regime.py:91-134`
- `test_regime_hysteresis.py:167-183`

当前 probe eligibility 仍是近似实现：

## 8. 今日最终修复建议

上线前最小修补包建议只做四件事：

1. 补 probe slot 全链路：
   - `_can_route_probe_short()` 检查 pending probe；
   - final slot gate 增加 probe 分支；
   - Ranker 支持 `available_probe`；
   - 同批 buffer 内最多 selected 1 个 probe。
2. `_record_rejected_plan()` 支持显式 attribution，所有 reject 路径传 `_rejection_attribution()`。
3. probe eligibility 加 liquidity gate，并至少把 trigger reason 写入 attribution。
4. PA 补漏仓位路径复用 setup 的 position normalization。

## 9. 最终放行判断

当前状态比第三次审计更接近验收，但仍不建议直接扩大 live。可以允许：

- 继续 paper/testnet；
- 或在严格单仓、人工监控、probe disabled 的情况下做极小额灰度。

不建议允许：

- 打开 probe_short 后直接 live 扩量；
- 把 shadow ledger 胜率当真实成交胜率；
- 用当前 event_backtest 结果直接调低 live 参数；
- 在没有 48h paper/testnet 样本前提高 `MAX_TRADE_AMOUNT` 或主并发。

本次最终审计的关键判断：**low R:R long 主体链路基本可观察，short guard 主体链路基本可回滚；剩余最大风险集中在 probe_short 的 slot/pending 体系和严格触发条件。**
