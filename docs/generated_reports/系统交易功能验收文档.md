# 系统交易功能验收文档

## 1. 验收目的

本验收文档用于验证交易系统在全局风控、影子账户、实盘执行、持仓对账、LLM 降级和 Telegram 控制方面是否满足需求文档要求。

验收重点不是策略收益，而是交易系统在异常、熔断、恢复和状态不一致情况下是否保持可控、可追踪、可复盘。

## 2. 验收范围

验收模块：

- Executor。
- PaperExecutor。
- Portfolio RiskGuard。
- Judge。
- Telegram Notifier。
- Position Analyst。
- Reviewer。
- 交易账本与结构化日志。

验收场景：

- 正常开仓。
- 低置信度拒单。
- 熔断触发。
- 熔断期间拒绝实盘和影子账户开仓。
- Telegram 解除熔断。
- 解除前持仓对账。
- 对账失败暂停交易。
- LLM 失败规则降级。
- 行情源失败告警。
- 每日交易报告生成。

## 3. 验收环境

基础环境：

- Python 运行环境与项目依赖已安装。
- OKX API 使用测试或小额实盘权限。
- Telegram Bot 已配置。
- LLM 服务可配置为正常、失败、超时三种模式。
- 初始逻辑账户权益为 300 USDT。

建议配置：

- 单笔最大保证金：30 USDT。
- 默认杠杆：5x。
- 最大活跃标的：5。
- 开仓置信度阈值：60。
- 连续亏损熔断阈值：3 次。

## 4. 验收数据与证据

验收需要保留以下证据：

- 主运行日志。
- Executor 日志。
- PaperExecutor 日志。
- RiskGuard 日志。
- Telegram 命令日志。
- 交易账本文件。
- 对账结果文件。
- 测试报告。

每个验收项必须给出：

- 测试时间。
- 测试输入。
- 期望结果。
- 实际结果。
- 日志证据。
- 验收结论。

## 5. 功能验收项

### 5.1 系统启动与配置摘要

验收步骤：

1. 启动交易系统。
2. 查看主日志配置摘要。
3. 确认所有核心 agent 已启动。

通过标准：

- 日志包含交易所、杠杆、单笔最大保证金、最大回撤、每日硬熔断、连续亏损熔断、研判周期、最大活跃标的、逻辑账户拆分。
- Market Scanner、Research、Censor、Router、Collector、Tech Analyst、Judge、Executor、PaperExecutor、RiskGuard、Position Analyst、Telegram 均启动成功。

失败标准：

- 任一核心 agent 未启动且系统仍允许实盘开仓。
- 配置摘要缺少关键风控参数。

### 5.2 正常交易决策与开仓

验收步骤：

1. 构造一个置信度大于等于 60 的 open 信号。
2. Judge 生成交易计划。
3. Executor 执行下单。
4. RiskGuard 记录持仓。
5. PaperExecutor 根据配置执行镜像模拟。

通过标准：

- 交易计划包含 entry、SL、TP、杠杆、保证金、费用、EV。
- Executor 日志包含订单提交和成交记录。
- RiskGuard 日志包含持仓记录。
- PaperExecutor 在 `mirror_risk=true` 时记录对应模拟仓位。
- 交易账本生成同一个 `trade_id` 的生命周期事件。

失败标准：

- 实盘成交后 RiskGuard 未记录持仓。
- PaperExecutor 与实盘状态不一致且无标记。
- 缺少交易生命周期记录。

### 5.3 低置信度拒单

验收步骤：

1. 构造一个 open 信号，置信度小于 60。
2. 发送至 Executor。
3. 检查是否拒绝开仓。

通过标准：

- Executor 不下单。
- 日志记录 `skip_low_confidence` 或等价原因。
- 记录实际置信度和阈值。
- PaperExecutor 不模拟开仓，除非明确处于独立模拟模式。

失败标准：

- 置信度不足仍实盘开仓。
- 仅记录 hold，未说明拒单原因。

### 5.4 熔断触发

验收步骤：

1. 构造连续亏损达到阈值。
2. 触发 RiskGuard 熔断。
3. 检查 Executor、PaperExecutor、Judge 后续行为。

通过标准：

- RiskGuard 记录 `halted=true`、`reason=consecutive_losses`。
- Executor 停止新开仓。
- PaperExecutor 在 `mirror_risk=true` 时停止新模拟开仓。
- Telegram 推送熔断原因、触发时间、持仓状态。
- 系统允许保护性平仓。

失败标准：

- 熔断后仍新增实盘开仓。
- 熔断后 PaperExecutor 仍无标记地新增模拟仓。
- 熔断状态重启后丢失。

### 5.5 熔断期间拒绝交易

验收步骤：

1. 在熔断状态下发送 open_long、open_short、hold、close 指令。
2. 检查执行层行为。

通过标准：

- open_long、open_short 被拒绝。
- 拒绝日志包含 `skip_halted` 或 `[熔断] 拒绝执行`。
- close 指令按保护性平仓策略处理：允许降低风险的平仓，不允许增加风险的动作。
- PaperExecutor 不新增开仓。

失败标准：

- 熔断期间仍执行新增风险动作。
- 拒绝日志缺少熔断原因。

### 5.6 Telegram 解除熔断

验收步骤：

1. 在熔断状态发送 `/resume`。
2. 系统进入解除流程。
3. 自动触发持仓对账。

通过标准：

- 日志记录 Telegram 命令来源。
- 系统记录 `resume_requested`。
- 执行持仓对账。
- 对账成功后记录 `resume_completed`。
- 对账失败则进入 `resume_pending_reconciliation`，不恢复新开仓。

失败标准：

- `/resume` 后未对账就恢复新开仓。
- Telegram 命令来源未记录。
- 对账失败仍恢复交易。

### 5.7 持仓对账

验收步骤：

1. 构造四类持仓状态：交易所、Executor、本地账本、RiskGuard、PaperExecutor。
2. 制造一致和不一致两组数据。
3. 触发 `/reconcile`。

通过标准：

- 一致时输出 `matched`。
- RiskGuard 缺失时输出 `missing_in_risk_guard`。
- Executor 缺失时输出 `missing_in_executor`。
- 影子账户不一致时输出 `paper_live_mismatch`。
- 外部平仓时输出 `external_close_detected`。
- 不一致时暂停新实盘开仓。

失败标准：

- 状态不一致但系统继续开仓。
- 对账结果没有写入日志或文件。

### 5.8 LLM 降级

验收步骤：

1. 模拟 LLM 返回 400。
2. 模拟 LLM 返回 503 `model_not_found`。
3. 模拟 LLM 输出 JSON 格式错误。
4. 检查系统是否规则降级。

通过标准：

- 日志记录失败模型、错误类型、状态码、标的。
- 系统标记 `rule_fallback=true`。
- 连续失败达到阈值后 Telegram 告警。
- 降级分析不得绕过风控和置信度阈值。

失败标准：

- LLM 失败导致交易主循环退出。
- 降级后直接提升风险或绕过阈值。
- 连续失败无告警。

### 5.9 行情源与新闻源异常

验收步骤：

1. 模拟新闻源返回 403。
2. 模拟 OKX ticker 请求失败。
3. 检查采集层和交易层行为。

通过标准：

- 新闻源失败记录 warning，不阻塞主流程。
- ticker 失败记录 warning，并避免使用空价格开仓。
- 连续行情失败触发告警或标的临时禁用。

失败标准：

- 空价格、旧价格或异常价格进入开仓计划。
- 外部源失败导致系统崩溃。

### 5.10 交易生命周期账本

验收步骤：

1. 执行一笔完整交易：开仓、减仓、平仓。
2. 查看账本事件。

通过标准：

- 每笔交易有唯一 `trade_id`。
- 事件顺序完整：decision_created、risk_checked、order_submitted、order_filled、position_registered、reduce_filled、close_filled、pnl_realized、risk_unregistered。
- 每个事件含时间、标的、方向、价格、杠杆、保证金、费用、PnL、来源 agent。

失败标准：

- 无法通过账本复原交易全过程。
- 开仓和平仓无法关联到同一 `trade_id`。

### 5.11 每日工作汇报生成

验收步骤：

1. 输入一个运行日志窗口。
2. 生成 Markdown 工作汇报。
3. 对照日志核查事实。

通过标准：

- 报告包含运行时间、配置摘要、筛选过程、交易明细、权益变化、持仓、熔断、恢复、异常和下一步建议。
- 实盘与 PaperExecutor 口径分开。
- 所有关键数字可追溯到日志。

失败标准：

- 报告混淆实盘和影子账户。
- 报告缺少熔断和异常降级说明。

## 6. 回归测试要求

必须通过以下测试集合：

- 风控熔断测试。
- PaperExecutor 熔断跟随测试。
- 持仓对账测试。
- 低置信度拒单测试。
- LLM 降级测试。
- Telegram 命令测试。
- 交易生命周期账本测试。

建议命令：

```bash
pytest test_risk_manager.py test_riskguard_upgrade.py test_paper_executor.py test_live_ledger.py test_reconciliation.py test_paper_live_isolation.py test_lifecycle_pnl.py
```

通过标准：

- 相关测试全部通过。
- 无跳过关键风控测试。
- 无需依赖真实大额交易。

## 8. 验收结论标准

通过：

- P0 验收项全部通过。
- P1 验收项无阻塞缺陷。
- 熔断、对账、拒单、降级均有日志证据。

有条件通过：

- P0 全部通过。
- P1 存在轻微日志字段缺失，但不影响交易安全。

不通过：

- 任一 P0 项失败。
- 熔断期间仍能新开实盘仓。
- 对账失败后仍能恢复交易。
- LLM 降级绕过风控。

## 9. P0 验收项

P0 项必须优先验收：

- A03 低置信度拒单。
- A04 熔断触发。
- A05 熔断期间拒绝交易。
- A06 Telegram 解除熔断前置对账。
- A07 持仓对账失败暂停交易。

P0 全部通过后，系统才允许进入下一阶段小额实盘连续运行。
