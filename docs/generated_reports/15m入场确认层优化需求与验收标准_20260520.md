# 15m 入场确认层优化需求与验收标准

日期：2026-05-20  
适用项目：`crypto-arbitrage` 多 Agent 合约交易系统  
需求主题：解决“1h/4h setup 成立，但实际开仓方向与 15m K 线短线趋势背驰”的入场时机问题

## 1. 背景

当前交易系统的主开仓标准是：

```text
1h 主信号
+ 4h / 1d 高周期方向过滤
+ RSI / R:R / EV / 流动性 / LLM 修正
+ Executor 风控复核
```

代码层面：

- `utils/config_loader.py` 默认 `interval="1h"`。
- `MultiDataCollector` 用 `self.interval` 拉主 K 线。
- `TechAnalyst` 用主 `klines` 生成 `rule_signal`、趋势、动量、支撑阻力。
- `MultiDataCollector` 额外采集 `4h` 和 `1d`，但没有独立采集 `15m` K 线。

因此系统能处理大周期方向和 1h setup，但缺少“开仓当下 15m 是否已经顺向”的入场确认层。用户观察到昨晚、今天上午和中午的开仓方向与 15m K 线趋势背驰，本质是短线入场 timing 缺失。

## 2. 最优方案

不要把主周期直接从 `1h` 改成 `15m`。直接切主周期会改变整个策略含义，使原本为 1h 设计的 MA、RSI、R:R、EV、deferred、LLM prompt 全部变成短周期策略，容易增加噪音和过度交易。

最优方案是增加独立的 `15m Entry Timing Filter`：

```text
4h / 1d：决定大方向是否允许
1h：决定是否存在交易 setup
15m：决定现在是否允许入场
```

核心原则：

- `15m` 不负责发现主交易机会。
- `15m` 不推翻高周期趋势。
- `15m` 只负责防止“逆短线动量立即开仓”。
- 当 `1h` setup 很强但 `15m` 反向时，不直接丢弃机会，而是转入 deferred entry，等待 15m 重新顺向。

## 3. 目标

1. 避免开多时 15m 明显空头、开空时 15m 明显多头。
2. 保留 1h setup 的交易机会，避免因 15m 短线回调直接错过。
3. 将“立即开仓”与“等待 15m 确认后开仓”区分开。
4. 让每笔开仓都能在日志、trade_decision、attribution 中看到 15m 是否确认。
5. 提供可回测、可单测、可人工复盘的验收标准。

## 4. 范围

### 4.1 本期范围

- 新增 15m K 线采集。
- TechAnalyst 输出 15m 趋势、动量、均线、RSI、最近 N 根方向。
- Judge 在所有 live open 和 deferred open 前执行 15m 入场过滤。
- 15m 反向时将强 setup 转入 deferred entry。
- 15m 重新顺向时允许 deferred entry 触发。
- 日志、Telegram、Reviewer attribution 增加 15m 相关字段。
- 单元测试、集成测试、回放验收标准。

### 4.2 非本期范围

- 不把主交易周期改成 15m。
- 不新增 15m 独立策略。
- 不扩大仓位。
- 不增加新交易所。
- 不让 LLM 绕过 15m 过滤。

## 5. 功能需求

### RQ-15M-01：采集 15m K 线

`MultiDataCollector` 必须在低频或中频采集中额外获取 15m K 线：

```text
fetch_ohlcv(symbol, "15m", limit=100)
```

发布到 `market_data`：

```json
{
  "klines": "...当前主周期，默认1h",
  "klines_15m": "...15m K线",
  "klines_4h": "...4h K线",
  "klines_1d": "...1d K线"
}
```

要求：

- `klines_15m` 缺失时不应让系统崩溃。
- 是否缺失必须进入 `data_quality`。
- 15m 缺失时默认策略为保守：新开仓不提高置信度；可配置是否禁止开仓。

建议配置：

```yaml
entry_timing_15m_enabled: true
entry_timing_15m_required: true
entry_timing_15m_limit: 100
```

### RQ-15M-02：计算 15m 入场状态

`TechAnalyst` 必须基于 `klines_15m` 输出：

```json
{
  "entry_timing": {
    "tf_15m_available": true,
    "tf_15m_bias": "bullish | bearish | neutral",
    "tf_15m_ma_alignment": "bullish | bearish | neutral",
    "tf_15m_rsi": 0,
    "tf_15m_momentum": "rising | falling | flat",
    "tf_15m_recent_closes": "up | down | mixed",
    "tf_15m_confirm_long": true,
    "tf_15m_confirm_short": false,
    "tf_15m_block_long": false,
    "tf_15m_block_short": true,
    "tf_15m_reason": "..."
  }
}
```

推荐计算逻辑：

```text
15m MA：
- ma_fast_15m = close rolling 7
- ma_slow_15m = close rolling 25

15m RSI：
- RSI 14

15m recent closes：
- 最近 3 根已闭合 15m close 连续上行 => up
- 最近 3 根已闭合 15m close 连续下行 => down
- 其他 => mixed
```

注意：

- 必须使用已闭合 K 线，不能用正在形成的最后一根 K 线做确认。
- 当前 `TechAnalyst` 对主周期使用 `df.iloc[-2]`，15m 也应保持同样原则。

### RQ-15M-03：开仓硬过滤

Judge 在发布任何实盘 `open_long` / `open_short` 前，必须执行 15m 入场过滤。

开多禁止条件：

```text
tf_15m_block_long = true，当满足任一组合：
1. 15m MA bearish 且 RSI < 48
2. 15m 最近 3 根已闭合 close 连续下行，且 RSI < 50
3. 15m bias bearish 且 momentum falling
```

开空禁止条件：

```text
tf_15m_block_short = true，当满足任一组合：
1. 15m MA bullish 且 RSI > 52
2. 15m 最近 3 根已闭合 close 连续上行，且 RSI > 50
3. 15m bias bullish 且 momentum rising
```

通过条件：

```text
open_long:
- tf_15m_confirm_long = true
- 或 15m neutral 且 1h score 极强且 4h/1d 同向

open_short:
- tf_15m_confirm_short = true
- 或 15m neutral 且 1h score 极强且 4h/1d 同向
```

建议默认：

```text
15m 明确反向 => 禁止立即 live open
15m neutral => 允许强信号，小信号等待
15m 同向 => 允许正常进入后续 EV/R:R/风控
```

### RQ-15M-04：强 setup 反向时转 deferred entry

当 1h setup 达标，但 15m 明确反向时，不应简单 `hold` 丢弃机会。

应改为：

```text
1h setup strong + 15m reverse
  -> action=hold
  -> reason=15m_timing_blocked
  -> state.deferred_entry = {
       action,
       signal_price,
       signal_score,
       target_price,
       created_at,
       entry_type="deferred_15m_confirmation",
       timeout_hours
     }
```

推荐 timeout：

```text
rule_signal + HTF 同向：6 小时
ma_aligned + HTF 同向：4 小时
普通强信号：2 小时
```

### RQ-15M-05：deferred 触发必须二次确认 15m

现有 deferred pullback/chase 触发时，必须额外检查 15m。

允许触发开多：

```text
- 15m 不 bearish
- RSI >= 45
- 最近 3 根 close 不连续下行
```

允许触发开空：

```text
- 15m 不 bullish
- RSI <= 55
- 最近 3 根 close 不连续上行
```

如果 deferred 到价但 15m 仍反向：

```text
保持 deferred 或继续 hold
不得强行开仓
```

### RQ-15M-06：归因字段

每个 `trade_decision` 的 `attribution` 必须增加：

```json
{
  "tf_15m_bias": "bullish",
  "tf_15m_rsi": 53.2,
  "tf_15m_ma_alignment": "bullish",
  "tf_15m_recent_closes": "up",
  "tf_15m_entry_status": "confirmed | blocked | neutral | unavailable",
  "tf_15m_block_reason": ""
}
```

用于：

- Reviewer 复盘。
- Telegram 摘要。
- 后续按 15m 入场状态统计胜率。

### RQ-15M-07：配置开关

新增配置项：

```python
entry_timing_15m_enabled = True
entry_timing_15m_required = True
entry_timing_15m_neutral_allows_strong_signal = True
entry_timing_15m_strong_score_threshold = 70
entry_timing_15m_defer_on_block = True
entry_timing_15m_timeout_hours = 4
```

含义：

- `enabled=false`：完全关闭 15m 入场确认。
- `required=true`：15m 数据缺失时禁止新开仓。
- `neutral_allows_strong_signal=true`：15m 中性时允许强 1h setup。
- `defer_on_block=true`：15m 反向时转 deferred，而不是直接丢弃。

## 6. 决策流程

优化后的开仓流程：

```text
market_data
  -> 1h klines + 15m klines + 4h + 1d
  -> TechAnalyst
      - 1h setup
      - 4h/1d bias
      - 15m entry_timing
  -> Judge
      1. data_quality
      2. concurrent limit
      3. cooldown
      4. 1h score threshold
      5. LLM correction
      6. RSI hard ban
      7. R:R / EV
      8. 15m entry timing filter
      9. publish live open or deferred hold
  -> Executor
      - balance/risk/precheck
      - order submit
```

关键顺序建议：

```text
15m filter 应放在“已确定有开仓意图”之后、“发布 trade_decision open”之前。
```

不建议太早放在 score 计算前，否则会污染 1h setup 本身，导致复盘时分不清“没有机会”还是“有机会但 timing 不好”。

## 7. 验收标准

### 7.1 数据采集验收

通过标准：

- `market_data` payload 包含 `klines_15m`。
- `klines_15m` 至少 50 根。
- `data_quality` 包含 15m 可用性字段，例如 `tf_15m_ok=true/false`。
- 15m 缺失时日志明确记录，不静默忽略。

失败标准：

- 没有 `klines_15m` 但系统仍按“15m confirmed”处理。
- 15m fetch 失败导致整个 market_data 不发布。

### 7.2 TechAnalyst 验收

构造 15m bearish 数据：

```text
ma_fast_15m < ma_slow_15m
RSI < 48
最近 3 根 close 下行
```

通过标准：

```json
{
  "tf_15m_bias": "bearish",
  "tf_15m_block_long": true,
  "tf_15m_confirm_short": true
}
```

构造 15m bullish 数据：

```text
ma_fast_15m > ma_slow_15m
RSI > 52
最近 3 根 close 上行
```

通过标准：

```json
{
  "tf_15m_bias": "bullish",
  "tf_15m_block_short": true,
  "tf_15m_confirm_long": true
}
```

### 7.3 Judge 开多过滤验收

输入：

```text
1h score = +75
4h bias = bullish
1d bias = bullish
15m bias = bearish
15m RSI = 42
最近 3 根 15m close 下行
```

通过标准：

- 不发布 `open_long`。
- 发布 `hold`。
- `reasoning` 包含 `15m_timing_blocked` 或等价描述。
- 若 `entry_timing_15m_defer_on_block=true`，写入 `deferred_entry`。
- `risk_warnings` 包含 `15m_bearish_against_long`。

失败标准：

- 直接发布 `open_long`。
- 仅因 LLM 或低置信度 hold，未说明 15m 反向。

### 7.4 Judge 开空过滤验收

输入：

```text
1h score = -75
4h bias = bearish
1d bias = bearish
15m bias = bullish
15m RSI = 61
最近 3 根 15m close 上行
```

通过标准：

- 不发布 `open_short`。
- 发布 `hold`。
- 若配置开启，进入 deferred。
- `risk_warnings` 包含 `15m_bullish_against_short`。

### 7.5 15m 同向放行验收

输入：

```text
1h score = +65
4h bias = bullish
15m bias = bullish
15m RSI = 54
最近 3 根 15m close mixed/up
R:R 和 EV 通过
```

通过标准：

- 允许继续通过 Judge 后续风控。
- 若其他门槛均通过，可发布 `open_long`。
- `attribution.tf_15m_entry_status = "confirmed"`。

### 7.6 15m 中性强信号验收

输入：

```text
1h score = +78
4h/1d bullish
15m bias = neutral
15m RSI = 50
```

通过标准：

- 若 `entry_timing_15m_neutral_allows_strong_signal=true`，允许继续。
- `attribution.tf_15m_entry_status = "neutral"`.
- 日志说明 `15m neutral but strong setup allowed`。

### 7.7 15m 缺失验收

输入：

```text
klines_15m = []
entry_timing_15m_required = true
```

通过标准：

- 不允许新开仓。
- 发布 hold 或跳过 open。
- 原因包含 `15m_unavailable`。

当：

```text
entry_timing_15m_required = false
```

通过标准：

- 不因 15m 缺失直接失败。
- attribution 标记 `tf_15m_entry_status = "unavailable"`。
- 不得因为 15m 缺失提高 confidence。

### 7.8 deferred 二次确认验收

场景：

```text
第一次：1h bullish setup，但 15m bearish -> deferred
第二次：价格到达目标，但 15m 仍 bearish -> 不开仓
第三次：15m 转 neutral/bullish -> 允许重新构建 plan
```

通过标准：

- 第一次不 live open。
- 第二次不 live open。
- 第三次才允许进入 EV/R:R/Executor。
- 日志能看到完整状态迁移。

### 7.9 回放验收

使用昨晚、今天上午和中午出现背驰问题的真实 K 线窗口回放。

通过标准：

- 原本背驰开仓的时间点，在新规则下不会立即 live open。
- 如果后续 15m 顺向确认出现，系统可以延迟开仓。
- 如果 15m 一直反向直到 timeout，系统放弃该 setup。
- 回放结果中 `15m_timing_blocked` 事件可被统计。

## 9. 日志与复盘口径

每次因 15m 阻止开仓，日志必须包含：

```text
symbol
intended_action
1h_score
4h_bias
1d_bias
15m_bias
15m_rsi
15m_recent_closes
block_reason
deferred_created
```

Reviewer 应按 `tf_15m_entry_status` 统计：

```text
confirmed 入场胜率
neutral 入场胜率
unavailable 入场胜率
blocked 后若继续追踪的机会成本
```

## 10. 成功指标

上线后 7 天内观察：

1. 与 15m 明确反向的 live open 数量降为 0。
2. 因 `15m_timing_blocked` 转 deferred 的 setup 有完整日志。
3. deferred 后重新顺向入场的交易单独统计胜率。
4. 交易频率可以下降，但平均入场后 30 分钟最大反向浮亏应下降。
5. 不得出现 15m 数据缺失导致系统崩溃。

## 11. 推荐实现顺序

1. `MultiDataCollector` 增加 `klines_15m`。
2. `TechAnalyst` 增加 `_analyze_entry_timing_15m()`。
3. `tech_analysis` payload 增加 `entry_timing`。
4. `Judge` 增加 `_check_15m_entry_timing()`。
5. live open 前调用 15m filter。
6. deferred pullback/chase 触发前调用 15m reconfirm。
7. attribution、日志、Reviewer 字段接入。
8. 增加单测与回放验收。

## 12. 最终判定

本优化的目标不是提高信号数量，而是提高入场质量。

合格标准只有一个：

```text
系统不得在 15m 明确反向时立即开 live 仓。
```

强 1h setup 遇到 15m 反向时，正确行为是：

```text
不立即开仓
保留机会
等待 15m 重新顺向
再重新经过 EV / R:R / 风控验证
```
