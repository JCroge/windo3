## 3. 阻塞 Phase 2 的缺口

### Blocker 1：EventBacktest 未同构 Phase 1 live 策略

位置：

- `event_backtest.py`

当前 `EventBacktest` 仍使用单一 `rr_floor` 和简化入场评分，不支持以下 Phase 1 行为：

- `regime` 列或 RegimeManager 等价状态。
- long/short/regime 不同 R:R floor。
- bullish short guard。
- low R:R long 仓位缩放和 extra slot。
- probe_short。
- side/regime/slot 分项 PF、胜率、样本数。
- validation 样本不足标记。

影响：

- `AC-BT-01/02/03` 未通过。
- Phase 2 若做 side/regime Bayesian EV，会缺少可信回测基线。
- 系统仍可能依赖 18 小时、21 个样本做参数判断，过拟合风险没有被工程化消除。

Phase 2 前置要求：

- EventBacktest 必须能复现 Phase 1 live 的核心放行/拒绝逻辑。
- 回测报告必须输出 `side x regime x slot_type` 分项指标。
- 样本不足时必须显式标记 `insufficient_sample=true`，不得输出上线建议。

### Blocker 2：Reviewer 只有字段落库，没有分层策略复盘

位置：

- `agents/trading/reviewer.py`

当前 Reviewer 已保存 `entry_regime/raw_regime/rr_policy/slot_type/is_probe/is_low_rr`，但 `_calculate_rolling_metrics()` 和 `strategy_review` 仍只输出全局 rolling metrics。

缺失：

- long/short 分项。
- bullish/mixed/bearish/choppy 分项。
- low_rr_extra/probe_short/main slot 分项。
- `side x regime` 的 PF、胜率、样本数。
- shadow ledger 与 live/paper 的对照摘要。

影响：

- Judge 仍只能消费全局 `_recent_win_rate/_recent_profit_factor`。
- Phase 2 的 side/regime Bayesian EV 没有稳定输入。
- low R:R long 和 bullish short 的真实贡献无法被独立观测。

Phase 2 前置要求：

- `strategy_review` 至少增加 `metrics_by_side`、`metrics_by_regime`、`metrics_by_slot_type`。
- 每个分项必须包含 `trade_count/win_rate/profit_factor/total_pnl/gross_profit/gross_loss`。
- 样本少于阈值时，明确标记样本不足，不能参与自动参数收紧或放宽。

### Blocker 3：PositionAnalyst 尚未实现 entry_regime grace 与 current_regime 闭环

位置：

- `agents/trading/position_analyst.py`

当前 PA 已保存 `entry_regime`，但没有 current regime 输入，也没有实现 Phase 1 PRD 要求的 60 分钟 regime grace。

缺失：

- review context 未包含 `current_regime`。
- 持仓打开后 60 分钟内，regime 从 bullish 抖到 mixed 的保护逻辑未实现。
- regime 连续反向确认与 15m 同向反转后再减仓的规则未实现。
- low R:R long 和 probe_short 只有部分保护，没有完整生命周期规则。

影响：

- AC-REG-04 未完全通过。
- 后续 Phase 2 如果引入更细的 regime EV，PA 可能仍以旧逻辑处理持仓。

Phase 2 前置要求：

- PA 需要接收或查询 current regime snapshot。
- review context 必须同时输出 `entry_regime/current_regime/regime_age/grace_active`。
- low R:R long 在 60 分钟内不得仅因 bullish->mixed 抖动被减仓。
- probe_short 需要补齐最长持仓、0.5R 未达标退出、连续亏损冷却的验收测试。

## 4. 非阻塞但需在 Phase 2 前确认

### 4.1 Regime 持久化 freshness TTL

位置：

- `utils/market_regime.py`

`data/regime_state.json` 目前会恢复旧 `effective_regime`。如果系统停机较久后重启，可能短时间沿用旧 regime。

建议：

- 持久化 `updated_at`。
- 超过 30-60 分钟的状态只作为 hint，不作为 effective gate。
- 启动 warm-up 期 regime 默认为 `mixed` 或 `warming_up`。

### 4.2 daily bullish 下 strong short 语义

位置：

- `utils/market_regime.py`

`daily_bias` 已传入 `is_short_allowed()`，但当前没有使用。PRD 曾写明 daily 仍 bullish 时普通 short 应降级为 probe/shadow；如果现在选择允许 1h+4h 强反转覆盖 daily bullish，需要在 PRD 中明确改口径，并写入 attribution。

建议：

- 二选一，不要保留隐式规则：
  - 严格口径：`daily_bias == bullish` 时，bullish regime 下 short 只能 probe/shadow。
  - 反转口径：允许 1h+4h 强反转覆盖 daily bullish，但 attribution 标记 `daily_bullish_override=true`。

## 5. Phase 2 Go/No-Go 标准

只有同时满足以下条件，才建议创建正式 Phase 2 PRD 和验收标准：

1. EventBacktest 同构 Phase 1：支持 regime、side floor、short guard、low R:R scaling、probe_short，并输出分项指标。
2. Reviewer 输出分层 rolling metrics，并由 Judge 可读取或至少可用于离线评估。
3. PositionAnalyst 完成 `entry_regime/current_regime` 闭环和 60 分钟 grace 规则。
4. 至少 48 小时 paper/testnet 运行无异常，且有 rejected ledger/live/paper 三类样本。
5. low R:R long 样本不足时不得扩大 live 权限；probe_short 样本不足时不得提高仓位或杠杆。
6. 全量 pytest 继续通过。

## 6. 建议下一步

不要直接进入 Phase 2 的 side/regime Bayesian EV 实现。下一步应先做 **Phase 1.5：观测与回测同构补齐**。

Phase 1.5 最小范围：

1. EventBacktest 同构 Phase 1 live 策略。
2. Reviewer 增加 side/regime/slot 分层指标。
3. PositionAnalyst 增加 current regime 和 grace 规则。
4. 补充对应单测与一份 48 小时 paper/testnet 验收报告模板。

完成 Phase 1.5 后，再进入 Phase 2：

- side/regime Bayesian EV。
- 分层 prior 与样本不足 fallback。
- 参数只允许从观测指标中收敛，禁止直接用单窗口最优值上线。
