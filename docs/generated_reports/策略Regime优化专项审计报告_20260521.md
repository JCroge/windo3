## 1. 结论摘要

当前代码通过现有测试，但 Phase 8 不能按“完整验收通过”理解。现有实现已经完成了核心雏形：

- `RegimeManager` 已有 raw/effective regime 与 hysteresis。
- `Short Regime Guard` 已接入 Judge。
- `probe_short`、`low_rr_long` 的仓位/杠杆缩放已接入 Judge。
- `CounterfactualLedger` 已能记录并解析 shadow TP/SL。
- 关键功能都有环境变量开关。
- 默认 pytest 回归通过。

但从 PRD/AC 口径看，仍有几个阻塞缺口：

1. Judge 中 `_hold_reason()` 兜底返回被误移，弱 hold 可能产生 `reasoning=None`。
2. CounterfactualLedger 当前主要覆盖 short guard，被质量门、R:R、EV、15m、ranking 拒绝的“已有 plan 信号”未系统入账。
3. Shadow TP/SL 不是基于 `price_tick` 连续解析，而是只在 `tech_analysis` 到达时用快照价格检查。
4. `RR_FLOOR_LONG_BULLISH=1.30` 不是真实硬地板，强信号可在 `1.20 <= R:R < 1.30` 继续 live 入场。
5. `probe_short` 生命周期、冷却和“不得加仓”没有完整贯穿 PositionAnalyst/Executor。
6. Attribution 在成功开仓路径较完整，但在拒绝路径、PA、Reviewer、event_backtest 中没有形成闭环。
7. `event_backtest.py` 仍未同构 Phase 8 的 side/regime/low-RR/short-guard 行为。

因此建议结论为：

```text
工程回归：通过
PRD 功能验收：部分通过
是否建议直接进入小额 live：不建议
建议阶段：先修 P0/P1，再跑 48h paper/testnet 分阶段验收
```

## 3. 防误判说明

以下不是缺陷，是 PRD 明确设计：

1. `LOW_RR_EXTRA_SLOT=1` 是允许的附加观察槽，不应简单判定为违反 `MAX_CONCURRENT_POSITIONS`。正确审计点是：总风险口径是否清楚、是否只允许 low R:R long、是否计入风控和复盘。
2. Phase 1 明确不做价格触发分批止盈，所以不能要求 live 层新增 TP1 price monitor、自动撤单重设 SL 等复杂执行路径。
3. CounterfactualLedger 不要求覆盖所有 hold 标的，只要求覆盖“已经形成 plan 后被拒绝”的信号。
4. bullish regime 不等于完全禁空。PRD 允许强 short 和 `probe_short`。
5. PRD/验收文档优先级高于早期优化方案文档。

## 5. 阻塞问题 P0

### P0-1 `_hold_reason()` 兜底返回断裂

位置：

- `agents/trading/judge.py:1623`
- `agents/trading/judge.py:1645`

现象：

```python
def _hold_reason(self, tech: dict, score: float) -> str:
    ...
    if direction == 'neutral':
        return "趋势中性，无明确方向，观望"

def _get_rr_policy_label(...):
    ...
    return 'default'
    if abs(score) < 10:
        return "多空信号对冲，净得分接近零，观望"
    return "信号强度不足，观望"
```

`_hold_reason()` 对普通 bullish/bearish 弱信号没有兜底返回，可能产生 `reasoning=None`。原本兜底代码被移到 `_get_rr_policy_label()` 的 `return 'default'` 后方，且引用了不存在的 `score`。

影响：

- 弱信号 hold 的解释字段不稳定。
- 日志、Telegram、审计数据可能出现空理由。
- 现有测试没有覆盖该路径。

建议：

- 把 `abs(score)<10` 和 `"信号强度不足，观望"` 移回 `_hold_reason()`。
- 删除 `_get_rr_policy_label()` 中不可达代码。
- 补一个单测覆盖 bullish/bearish 非 extreme 且 `abs(score)<threshold` 的 hold reason。

### P0-2 CounterfactualLedger 未覆盖 PRD 要求的 rejected planned signals

PRD 要求：

- `docs/strategy_regime_optimization_prd_20260521.md:216`
- `docs/strategy_regime_optimization_acceptance_20260521.md:312`

当前实现：

- `agents/trading/judge.py:970` 只在 short guard 拒绝时调用 `record_rejection()`。

缺失路径：

- 质量门拒绝：`agents/trading/judge.py:915`
- R:R 过低拒绝或等待回调：`agents/trading/judge.py:1038`
- EV gate 拒绝：`agents/trading/judge.py:1158`
- 15m blocked/deferred：`agents/trading/judge.py:1185`
- Ranking 淘汰：`agents/trading/judge.py:1328`
- data degraded 属于无可靠 plan，可不入账；这点不应误判。

影响：

- Ledger 统计会严重偏向 short guard 样本。
- 无法验证 low R:R long 是否被误杀。
- 无法满足 AC-LEDGER-01。

建议：

- 增加统一 helper，例如 `_record_rejected_plan(symbol, action, plan, score, confidence, reason, tech, attribution=None)`。
- 所有“plan 已构建后拒绝”的路径统一调用。
- 对 ranking rejected 也写入 ledger，reason=`ranked_out`。
- hold-only 未形成 plan 的信号不写 ledger，并在报告中声明边界。

### P0-3 Shadow TP/SL 解析链路粒度不足

位置：

- `agents/trading/judge.py:56`
- `agents/trading/judge.py:424`
- `utils/counterfactual_ledger.py:71`

当前 Judge 只订阅 `tech_analysis:*`，不订阅 `price_tick:*`。Ledger 的 `check_price()` 能按价格解析 TP/SL，但 Judge 只有在下一次 tech_analysis 到来时才检查。

影响：

- 无法精确判断 1h 内先 TP 后 SL，或先 SL 后 TP。
- 标的移除后不再有 tech_analysis，shadow 只能过期。
- AC-LEDGER-02 的“输入后续 price_tick”在系统链路上不成立。

建议：

- 让 `CounterfactualLedger` 由独立 `SignalShadowTracker` 或 PaperExecutor 订阅 `price_tick:*`。
- 若保留在 Judge，至少把 Judge subscriptions 加上 `price_tick:*` 并仅处理 ledger，不触发决策。
- 同根 K/同一 tick 同时触发 TP/SL 时明确最保守归因。

### P0-4 `RR_FLOOR_LONG_BULLISH=1.30` 不是硬地板

位置：

- `agents/trading/judge.py:1031`
- `agents/trading/judge.py:1038`
- `agents/trading/judge.py:1051`

PRD 定义 low R:R long：

```text
effective_rr >= RR_FLOOR_LONG_BULLISH
AND effective_rr < 1.5
```

当前行为：

- bullish long 且 low_rr_slot 开启时，`min_rr=1.30`。
- 但如果 `rr < min_rr` 且 `rr >= 1.2` 且 `abs(score)>=50`，代码会缩仓后继续 live 入场。

影响：

- 配置名 `RR_FLOOR_LONG_BULLISH` 语义失真。
- 可能 live 放行 PRD 未授权的 `1.20 <= R:R < 1.30` 交易。

建议：

- 如果 `RR_FLOOR_LONG_BULLISH` 是硬地板：`rr < min_rr` 一律 hold/shadow。
- 如果强信号豁免是有意设计：把参数改名或补文档，例如 `RR_CHASE_FLOOR_STRONG_SIGNAL=1.20`，并要求 attribution 标出 `rr_policy=strong_signal_chase_below_floor`。

### P0-5 Probe short 生命周期和不得加仓未闭环

位置：

- `agents/trading/judge.py:353`
- `agents/trading/judge.py:373`
- `agents/trading/position_analyst.py:91`
- `agents/trading/position_analyst.py:332`

当前行为：

- `probe_short` open 成功时依赖 `result.attribution.is_probe` 设置 `_probe_short_active`。
- 只有 `force_closed` 且 symbol 匹配时清理 active 并累计 SL。
- 普通 close、TP、外部平仓不会清理 active，也不会根据 probe 亏损统计 cooldown。
- PA 不保存 `is_probe/slot_type`，仍可能按普通持仓发加仓信号。

影响：

- probe 可能永久占用 `_probe_short_active`。
- probe 亏损冷却不可靠。
- 违反 PRD “probe_short 不得加仓、最多 1 个、亏损 2 次冷却 24h”。

建议：

- execution_result close/risk_reduced/closed_externally/force_closed 都要检查 attribution 或 positions 中的 probe 标记。
- 持仓状态中保存 `slot_type/is_probe/is_low_rr/entry_regime`。
- PA 对 `is_probe=True` 禁止 add，并增加最长持仓 2h 与 0.5R/15m 退出逻辑。

## 7. 中风险问题 P2

### P2-1 Regime 持久化无 freshness TTL

位置：

- `utils/market_regime.py:284`

`data/regime_state.json` 会无条件恢复 `effective_regime` 和 `last_changed_at`。如果进程停了一段时间后重启，系统可能沿用旧 regime，直到新 tech cache 足够覆盖。

建议：

- 持久化 `updated_at`。
- 超过 30-60min 后启动时只作为 hint，不作为 effective gate。
- 首轮 active symbols 不足时 regime 标记 `mixed` 或 `warming_up`。

### P2-2 strong short 的 daily bullish 降级未落实

位置：

- `utils/market_regime.py:67`

PRD 说明：daily 不要求必须 bearish，但如果 daily 仍 bullish，普通 short 必须进一步降级为 `probe_short` 或 shadow。当前 `daily_bias` 传入但未使用，只要 1h 和 4h bearish votes 达到 2，daily bullish 仍可 strong short 放行。

建议：

- 明确解释 PRD 语义。
- 若按 PRD 严格执行：`daily_bias == 'bullish'` 时普通 short 不直接 live，只允许 probe/shadow。
- 若允许 1h+4h 强反转覆盖 daily bullish，需要补充 PRD 变更和 attribution。

### P2-3 参数暴露较多，容易偏离“Phase 1 不调参”原则

## 11. 量化公式审计

### 11.1 Score

位置：`agents/trading/judge.py:1678`

核心结构：

- rule_signal 主驱动：entry ±35。
- MA aligned 次驱动：±20。
- trend、RSI divergence、OI divergence、whale、crowd、taker、HTF bias 加减分。
- RSI 极端保护对反向追单做 cap。
- 4h RSI 极端时对同向 score 50% 衰减。

评价：

- 方向保护较多，尤其对 RSI 极端和 4h RSI 有防追高/追空逻辑。
- 与 Phase 8 long/short 分离目标相比，score 仍是全局单一评分，directional EV 尚未落地。

### 11.2 SL/TP/R:R

位置：

- `agents/trading/judge.py:1868`
- `agents/trading/judge.py:2001`
- `agents/trading/judge.py:2028`

公式：

- SL 基于结构位 + ATR cap。
- TP 至少保持 `SL × 1.5` 的距离。
- `effective_rr = (gross_profit - total_cost) / (gross_loss + total_cost)`。

注意：

- TP 生成仍默认保底 1.5R，因此 low R:R 多数来自成本侵蚀，而非 TP 目标低于 1.5R。
- 文案中多处仍写 `R:R<1.5`，在 dynamic `min_rr=1.30` 场景下容易误导日志。

### 11.3 EV

位置：

- `agents/trading/judge.py:1900`
- `agents/trading/judge.py:1940`
- `agents/trading/judge.py:1958`

公式：

```text
EV = p_win * net_profit - (1 - p_win) * net_loss
```

当前 `p_win`：

- rolling 胜率样本足够时用全局 rolling。
- 样本不足时用 Bayesian prior。

风险：

- 仍是全局 p_win，不是 side/regime/archetype 分层。
- PRD 的核心问题之一是 long/short 表现分化；当前 EV 仍可能让 short 亏损拖累 long，或 long 胜率给 short 背书。

建议：

- 下一阶段引入 `(side, regime, slot_type/archetype)` 分层统计。
- Reviewer 先补字段，否则无法计算。

### 11.4 Risk Budget

位置：`agents/trading/judge.py:2104`

公式：

```text
margin_usdt = min(balance * 10%, max_trade_amount)
max_loss_usdt = balance * 5%
raw_leverage = max_loss_usdt / (margin_usdt * sl_dist)
notional = margin_usdt * leverage
actual_max_loss = margin_usdt * sl_dist * leverage
```

评价：

- `size_usdt` 语义是保证金，和 docs/development.md 一致。
- 低 R:R long 与 probe short 后续有缩仓/杠杆 cap。
- Live executor 还会 cap `size_usdt <= max_trade_amount`。

需要补：

- low_rr/probe 的实际风险应进入 Reviewer/PA/metrics。
- `LOW_RR_EXTRA_SLOT` 是 PRD 明确允许的附加槽，不是 bug；但启动 banner 和 runbook 应写清总 live slot 可能为 `MAX_CONCURRENT_POSITIONS + LOW_RR_EXTRA_SLOT`。
