# 系统交易能力优化需求文档

## 1. 背景

2026-05-19 22:49 至 2026-05-20 11:27 的系统交易运行中，主链路已完成市场扫描、研判、言官审查、标的路由、技术分析、裁判决策、执行、风控、Telegram 控制与影子账户记录。运行期间出现以下关键现象：

- PaperExecutor 影子账户从 300.00 USDT 启动，停止前权益为 296.84 USDT，约 -1.05%。
- 实盘执行层在 2026-05-20 06:52 触发 `consecutive_losses` 熔断，并拒绝新交易。
- 2026-05-20 10:52 通过 Telegram `/resume` 解除熔断。
- 解除后 SAHARA-USDT 触发实盘限价开仓，成交数量 840，成交价约 0.04。
- 熔断期间 PaperExecutor 仍记录了模拟开仓，说明影子账户与全局风控状态存在口径不一致。
- LLM 调用出现 400、503、JSON 解析失败等问题，系统能降级运行，但告警和风险可见性不足。

本需求文档用于定义下一阶段交易系统优化范围，确保实盘风控、影子账户、执行状态和异常降级具备一致、可追踪、可验收的行为。

## 2. 目标

1. 统一实盘执行层、PaperExecutor、RiskGuard 对熔断状态和持仓状态的理解。
2. 降低低置信度或弱信号环境下的无效试单和手续费消耗。
3. 提升 LLM 降级、行情源异常、新闻源异常的可观测性。
4. 建立可复盘的交易生命周期账本，覆盖开仓、减仓、平仓、拒单、熔断、恢复。
5. 保证 Telegram 风控命令具备明确的状态变更记录和权限边界。

## 3. 范围

### 3.1 本期范围

- 全局熔断状态同步。
- PaperExecutor 与实盘执行层隔离及一致性修复。
- 持仓账本与风控追踪状态对账。
- 低置信度交易过滤和重复信号冷却。
- LLM 降级告警与规则降级标记。
- 交易运行报告所需的结构化日志字段。

### 3.2 非本期范围

- 新策略因子研发。
- 新交易所接入。
- 实盘仓位规模扩大。
- 高级组合优化器。
- 前端可视化大盘。

## 4. 角色与模块

- Market Scanner：扫描交易标的并输出候选池。
- Research Agents：采集新闻、情绪、研判材料。
- Censor：对候选标的做反向审查。
- Symbol Router：维护活跃交易标的。
- Multi Data Collector：采集行情、K线、盘口等数据。
- Tech Analyst：输出技术趋势、强度、杠杆风险。
- Judge：生成交易决策和交易计划。
- Executor：负责实盘下单、拒单、平仓。
- PaperExecutor：负责影子账户模拟执行。
- Portfolio RiskGuard：负责组合风险、熔断、追踪止损。
- Position Analyst：负责持仓评估。
- Telegram Notifier：负责通知与远程命令。
- Reviewer：负责交易复盘。

## 5. 功能需求

### 5.1 全局熔断状态同步

系统必须维护统一的全局熔断状态，至少包含：

- `halted`: 是否处于熔断。
- `reason`: 熔断原因，例如 `consecutive_losses`、`daily_loss`、`flash_move_market`。
- `triggered_at`: 触发时间。
- `triggered_by`: 触发来源，例如 `risk_guard`、`executor`、`telegram`。
- `resume_at`: 解除时间。
- `resume_by`: 解除来源。

当全局熔断触发时：

- Executor 必须停止接收新开仓。
- PaperExecutor 必须停止新模拟开仓。
- Judge 可以继续输出分析和 hold 决策，但不得推动执行开仓。
- RiskGuard 必须继续追踪已有持仓并允许保护性平仓。
- Telegram 必须推送熔断原因、当前持仓、是否完成全平。

当全局熔断解除时：

- 必须记录解除来源。
- 必须重新同步实盘持仓、影子账户持仓、RiskGuard 状态。
- 若三方状态不一致，系统不得立即恢复新开仓，应进入 `resume_pending_reconciliation` 状态。

### 5.2 PaperExecutor 与实盘执行一致性

PaperExecutor 应支持两种模式：

- `mirror_risk=true`: 完全跟随实盘风控状态，熔断期间禁止新模拟开仓。
- `mirror_risk=false`: 允许独立模拟，但所有日志必须显式标记为独立模拟，不得被视为实盘风险状态。

默认要求 `mirror_risk=true`。

熔断期间，PaperExecutor 如收到 open 指令，应记录：

- 标的。
- 决策动作。
- 拒绝原因。
- 当前熔断原因。
- 来源 agent。

### 5.3 持仓状态对账

系统必须定期对账以下三类状态：

- 实盘交易所持仓。
- Executor 本地持仓。
- RiskGuard 追踪持仓。
- PaperExecutor 影子账户持仓。

对账结果必须输出：

- `matched`: 完全一致。
- `missing_in_risk_guard`: 执行层存在但风控未追踪。
- `missing_in_executor`: 风控追踪但执行层不存在。
- `paper_live_mismatch`: 影子账户与实盘口径不一致。
- `external_close_detected`: 检测到外部平仓。

当出现不一致：

- 实盘新开仓必须暂停。
- 允许保护性平仓。
- 必须发送 Telegram 告警。
- 必须写入结构化日志。

### 5.4 低置信度交易过滤

系统必须统一执行交易准入门槛：

- 默认开仓置信度阈值为 60。
- 若 LLM 观望但规则信号触发，仓位必须衰减，且需要二次确认。
- 置信度低于阈值的 open 信号不得进入实盘下单。
- 重复触发同一标的同方向信号时，应遵守冷却时间。

日志必须明确区分：

- `hold`: 策略主动观望。
- `skip_low_confidence`: 置信度不足跳过。
- `skip_halted`: 熔断跳过。
- `skip_cooldown`: 冷却跳过。
- `skip_reconciliation_pending`: 对账未完成跳过。

### 5.5 LLM 降级与异常告警

LLM 调用失败时，系统可以降级为规则分析，但必须记录：

- 失败模型。
- 错误类型。
- 错误状态码。
- 失败标的。
- 是否使用规则降级。
- 降级后的决策风险等级。

以下情况必须触发 Telegram 告警：

- 连续 3 次 LLM 失败。
- 5 分钟内 LLM 失败率超过 50%。
- 出现 `model_not_found`。
- 出现影响 JSON 解析的响应格式错误。

### 5.6 交易生命周期账本

每笔交易必须具备唯一 `trade_id`，生命周期包括：

- decision_created。
- risk_checked。
- order_submitted。
- order_filled。
- position_registered。
- reduce_submitted。
- reduce_filled。
- close_submitted。
- close_filled。
- pnl_realized。
- risk_unregistered。

每个阶段必须包含：

- 时间。
- 标的。
- 方向。
- 保证金。
- 杠杆。
- 入场价。
- 止损。
- 止盈。
- 手续费估算。
- 资金费率估算。
- realized PnL。
- unrealized PnL。
- 来源 agent。

### 5.7 Telegram 远程控制

Telegram 命令必须具备明确状态变更：

- `/halt`: 触发人工熔断。
- `/resume`: 请求解除熔断。
- `/status`: 查看系统状态。
- `/positions`: 查看持仓。
- `/reconcile`: 触发对账。

`/resume` 不应直接恢复新开仓，必须先完成对账。对账成功后恢复，失败则保持暂停。

## 6. 非功能需求

### 6.1 安全性

- 熔断状态优先级高于任何交易信号。
- 对账失败时禁止实盘新开仓。
- LLM 降级不得绕过风控。
- Telegram 控制命令必须限定授权来源。

### 6.2 可观测性

- 所有关键状态变更必须有结构化日志。
- 每 5 分钟输出账户权益、持仓数、未实现盈亏、风控状态。
- 异常必须分级：info、warning、critical。

### 6.3 可恢复性

- 系统重启后必须恢复熔断状态、持仓状态、交易账本。
- 如果历史状态不完整，应进入只读观察模式，不允许新开仓。

### 6.4 可测试性

- 熔断、解除熔断、对账、低置信度拒单、LLM 降级均需单元测试。
- 至少覆盖 PaperExecutor 与 Executor 的状态隔离测试。
- 至少覆盖一次端到端模拟运行。

## 7. 日志与报告要求

每日运行报告至少输出：

- 运行时间窗口。
- 启动配置摘要。
- 标的筛选过程。
- 实盘交易明细。
- 影子账户交易明细。
- 权益变化。
- 当前持仓。
- 熔断与恢复记录。
- 异常与降级记录。
- 下一步行动项。

## 8. 优先级

P0：

- 全局熔断状态同步。
- PaperExecutor 熔断跟随。
- 持仓对账失败禁止新开仓。

P1：

- 交易生命周期账本。
- LLM 降级告警。
- Telegram `/resume` 前置对账。

P2：

- 日报自动生成。
- 更细粒度策略表现归因。
- 异常趋势统计。

## 9. 成功标准

本期完成后，应满足：

- 熔断期间实盘和影子账户均不会新增开仓。
- 解除熔断前必须完成对账。
- 对账失败时不会恢复交易。
- 所有开仓、减仓、平仓、拒单、熔断、恢复均有结构化日志。
- LLM 大面积异常时系统能降级运行并明确告警。
- 每日工作汇报可从日志自动提取核心事实。
