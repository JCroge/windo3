## 1. 结论

第三轮更新比第二次审计有明显进展，尤其是：

- Regime hysteresis 的 `bullish -> mixed` 降级阈值问题已修正。
- 15m confirmation / pullback / chase 等 deferred 路径已接入统一 regime policy helper。
- low R:R extra slot 的 Ranker 记账开始区分 `main` / `low_rr_extra`。
- 低 R:R / probe 仓位参数已加入硬限制。
- PaperExecutor、PositionAnalyst、event_backtest 已补了一批 attribution、probe 生命周期和分层指标。
- 编译、专项测试、全量测试均通过。

但本轮仍不能判定 Phase 1C 可进入小额 live 扩量。核心原因不是测试失败，而是仍存在几个会影响真实交易行为的逻辑缺口：

1. `degrade_to_probe` 可绕过 `PROBE_SHORT_ENABLED=false`、probe 冷却和“同一时间最多 1 个 probe_short”的限制。
2. 重启后 `positions.json` 中的嵌套 attribution 没有被恢复成 slot/probe 状态，low R:R / probe 的持仓管理会退化。
3. `RANKING_ENABLED=false` 或主槽满时，预并发闸门与实际 slot 类型不一致，存在普通候选越过主槽上限发布 live open 的路径。
4. CounterfactualLedger 仍缺 `shadow_invalidated` 和完整 attribution，price_tick symbol 规范化也未完全闭环。
5. probe_short 早期反转触发条件仍是近似版，未严格实现 PRD 的 downcross / transition / 2h breadth 恶化等条件。

建议：先修复本报告 P0/P1，再进入 48h paper/testnet 验收；当前不建议扩大 live。

## 4. P0 / 阻塞问题

### P0-1 `degrade_to_probe` 绕过 probe 开关、冷却与并发限制

位置：

- `utils/market_regime.py:67-89`
- `agents/trading/judge.py:1083-1092`
- `agents/trading/judge.py:1743-1748`

当前 `RegimeManager.is_short_allowed()` 在 bullish regime 中遇到强 short 且 daily 仍 bullish 时返回：

```python
return True, "degrade_to_probe"
```

Judge 收到 `guard_reason == "degrade_to_probe"` 后，无条件把 plan 改成：

```python
plan["is_probe"] = True
plan["slot_type"] = "probe_short"
plan["size_usdt"] = MAX_TRADE_AMOUNT * probe_short_max_position_pct
plan["leverage"] <= probe_short_max_leverage
```

问题是该分支没有检查：

- `self._probe_short_enabled`
- `self._probe_short_active is None`
- `time.time() > self._probe_short_cooldown_until`
- `self._probe_short_max_concurrent`
- `is_probe_short_eligible(...)` 的市场级反转条件
- 标的级 `liquidity_score > 0`

影响：

- 即使 `.env` 设置 `PROBE_SHORT_ENABLED=false`，强 short + daily bullish 仍会被降级成 probe live plan。
- 已有 1 个 probe_short 时，第二个 strong short 仍可能被降级成 probe，违反“同一时间最多 1 个 probe_short”。
- 连续 2 次 probe SL 后的 24h 冷却可被 strong-short degrade 分支绕过。
- 该分支把“daily bullish 不允许普通 strong short”实现成“强制 probe”，但没有经过 probe 自身准入规则。

验收影响：

- AC-PARAM-02 失败。
- AC-SHORT-03 失败。
- AC-SHORT-04 失败。

建议修复：

1. 把 `degrade_to_probe` 也统一走一个 `_try_route_probe_short()` helper。
2. helper 必须同时检查 probe 开关、active/cooldown/concurrent、市场级早期反转、标的级条件。
3. 如果 daily bullish 但 probe 不可用，应 reject/shadow，而不是开普通 strong short 或强行 probe。
4. 为以下场景补测试：
   - `PROBE_SHORT_ENABLED=false` 时 strong short daily bullish 不生成 probe。
   - 已有 active probe 时第二个 degrade_to_probe rejected。
   - cooldown 未结束时 degrade_to_probe rejected。

## 5. P1 / 高优先级问题

### P1-1 `SHORT_REGIME_GUARD_ENABLED=false` 不完全回到旧逻辑

位置：

- `agents/trading/judge.py:1125-1150`
- `agents/trading/judge.py:1750-1762`
- `agents/trading/judge.py:148-153`

即使 `short_regime_guard_enabled=false`，bullish regime 下 short 仍会使用：

```python
min_rr = self._rr_floor_short_bullish  # 默认 1.80
```

这意味着关闭 short guard 后，short 的 R:R 地板仍从旧逻辑的默认 1.5 变成 1.8。按 PRD/验收，Phase 1 live 只允许 `RR_FLOOR_LONG_BULLISH` 和 `SHORT_REGIME_GUARD_ENABLED` 改变交易结果；关闭新增开关后应回到旧 Judge 规则。

影响：

- 回滚开关不能完全回滚行为。
- `RR_FLOOR_SHORT_BULLISH` 作为 env 可调项暴露，会改变 live 行为，但不是验收允许的两个 live 策略参数之一。

建议修复：

- `short_regime_guard_enabled=false` 时，short 的 `min_rr` 应回到 `rr_floor_default`。
- 如果保留 `rr_floor_short_bullish`，应作为 guard 内部固定参数或只在 guard 启用时生效。
- 增加 AC-PARAM-02 测试：所有新增开关 false 时，同一 short plan 走旧 R:R 地板。

### P1-2 重启恢复丢失 slot/probe attribution

位置：

- `executor.py:762-783`
- `agents/trading/judge.py:254-268`
- `agents/trading/position_analyst.py:42-48`
- `agents/trading/position_analyst.py:401-480`
- `agents/trading/executor.py:487-506`

真实 Executor 在持久化 position 时，新增字段放在：

```python
position["attribution"] = plan.get("attribution", {})
```

但 Judge 重启恢复时读取的是顶层字段：

```python
saved_positions[sym].get("slot_type", "main")
```

PositionAnalyst 重启加载 `data/positions.json` 时也只是原样读入，没有把嵌套 attribution 展开成：

- `is_probe`
- `is_low_rr`
- `slot_type`
- `entry_regime`

影响：

- low_rr_extra 持仓重启后会被 Judge 当成 `main`，slot occupancy 失真。
- probe_short 持仓重启后不会恢复 `_probe_short_active`，后续可能继续开第二个 probe。
- PA 重启后 `pos.get("is_probe")` 为 false，probe 禁止加仓和 2h 生命周期退出会失效。
- PA 重启后 `entry_regime` 可能变成 unknown，60min regime grace 失效。
- 外部 SL/TP 平仓通知只带 symbol/side/entry/amount，不带 attribution；重启后 Judge 无法把 probe SL 计入 probe 冷却。

建议修复：

1. 在 Judge 和 PA 的 `_load_positions()` 中统一 normalize：
   - 优先读顶层字段；
   - 顶层不存在时读 `position["attribution"]`；
   - 写回内存中的顶层 `slot_type/is_probe/is_low_rr/entry_regime`。
2. Judge setup 时如发现 `is_probe=true` 且仍有持仓，应恢复 `_probe_short_active=symbol`。
3. Executor 的 `_notify_removed_positions()` 应把 `pos_data["attribution"]` 透传到 `execution_result.result`。
4. 增加重启恢复测试：low_rr/probe positions.json 只有嵌套 attribution 时，Judge/PA 仍能恢复正确状态。

### P1-3 并发预闸门与最终 slot 类型不一致，`RANKING_ENABLED=false` 时可越过主槽上限

位置：

- `agents/trading/judge.py:500-533`
- `agents/trading/judge.py:1302-1324`
- `utils/candidate_ranker.py:55-58`

当前 `_make_decision()` 开头的预闸门逻辑是：

```text
main 满时，只要 low_rr 或 probe 还有空间，就不拦截，继续构建 plan/调用 LLM/走后续流程。
```

这对 low_rr_extra 是必要的，但问题是此时还不知道当前 symbol 最终会是 normal、low_rr 还是 probe。若 `RANKING_ENABLED=true`，普通候选最终会被 Ranker 根据 `slot_occupancy` reject；但若 `RANKING_ENABLED=false`，主路径会在 `agents/trading/judge.py:1324` 直接 publish open decision。

影响：

- ranking 关闭时，主槽已满但 low_rr/probe 还空，普通 high R:R 候选也可能发布 live open，突破 `MAX_CONCURRENT_POSITIONS` 主槽限制。
- ranking 开启时虽然 Ranker 会挡住 normal 候选，但会浪费 LLM/plan/ledger 资源，并造成 reject reason 排序靠后。

建议修复：

- 保留早期预闸门用于“所有槽都满”快速拒绝。
- 在 plan 已确定 `slot_type` 后、publish 或 ranker add 前再做一次 final slot gate：
  - `slot_type=main` 必须 `main_count < max_concurrent_positions`；
  - `slot_type=low_rr_extra` 必须 `low_rr_count < low_rr_extra_slot`；
  - `slot_type=probe_short` 必须满足 probe active/cooldown/concurrent。
- `RANKING_ENABLED=false` 时也必须走 final slot gate。

### P1-4 CounterfactualLedger 事件仍不满足 PRD 必填项

位置：

- `utils/counterfactual_ledger.py:28-61`
- `utils/counterfactual_ledger.py:71-141`
- `agents/trading/judge.py:1775-1784`
- `agents/trading/judge.py:430-435`

当前 ledger 已能记录：

- `rejected_plan_created`
- `shadow_tp`
- `shadow_sl`
- `shadow_expired`

但 PRD RQ-REG-06 明确要求还要记录：

- `shadow_invalidated`

此外 ledger record 仍缺少 trade decision attribution 中的关键字段：

- `raw_regime`
- `regime_confidence`
- `rr_policy`
- `slot_type`
- `blocked_by`
- `is_probe`
- `is_low_rr`

Judge 的 `_record_rejected_plan()` 只把 symbol、side、plan、regime、score、confidence、reason 传给 ledger，没有传 attribution。`price_tick` 分支也没有对 symbol 调 `to_internal()`，若上游发送 `BTC-USDT-SWAP` 或其他格式，ledger 的精确 symbol 匹配会漏解析 shadow TP/SL。

验收影响：

- AC-LEDGER-01 基本通过。
- AC-LEDGER-02 部分通过。
- RQ-REG-06 / `shadow_invalidated` 未通过。
- AC-OBS-01 部分失败。

建议修复：

- `record_rejection(..., attribution: dict = None)`，将 attribution 展平写入 record。
- 增加 `invalidate(symbol, reason, timestamp)` 或按反向信号/plan 失效条件写 `shadow_invalidated`。
- Judge `price_tick` 统一 `to_internal(symbol)` 后再调用 ledger。
- 增加测试覆盖 invalidated、嵌套 attribution、symbol normalization。

### P1-5 probe_short 触发条件仍是近似版，不是 PRD 的严格早期反转模型

位置：

- `utils/market_regime.py:91-134`
- `agents/trading/judge.py:1040-1048`
- `agents/trading/judge.py:1725-1733`
- `event_backtest.py:343-346`

PRD 对 probe_short 的市场级条件要求至少包含以下之一：

```text
1. BTC/ETH 4h RSI 从 >=75 下穿 70，且当前 4h 为放量阴线；
2. active_symbols 中 60% 以上 15m bias 从 bullish 转 neutral/bearish；
3. TopN 24h breadth 仍 bullish，但最近 2h breadth 明显恶化；
4. 资金费率极端偏多 + crowd 极端拥挤 + 15m 跌破关键均线。
```

当前实现的偏差：

- 条件 1 只看当前 `60 < tf_4h_rsi < 70` 和 `volume_ratio > 1.5`，没有保存 previous RSI，也没有确认“从 >=75 下穿 70”，没有检查 4h 阴线。
- 条件 2 只统计当前 15m bias 为 neutral/bearish 的比例，没有确认“从 bullish 转向”。
- 条件 3 未实现最近 2h breadth 明显恶化。
- 条件 4 只检查 funding/crowd，未要求 15m 跌破关键均线。
- 标的级条件只在 Judge 中零散检查 `abs(score)>=50`、15m confirm、RR>=1.3，`liquidity_score > 0` 没有作为 probe 专属硬条件表达。
- event_backtest 中 probe 更简化，只用 `rsi >= 70` 和 cooldown 近似，不可完全复现实盘条件。

影响：

- probe_short 可能过宽，尤其叠加 P0-1 后，会在 daily bullish 下过度试空。
- 回测 probe 样本与 live probe 样本不完全同构，AC-BT-01 只能算部分通过。

建议修复：

- RegimeManager 持久化 previous BTC/ETH 4h RSI、4h candle direction、15m breadth 快照。
- 为每条 probe 市场条件返回 reason，例如 `btc_4h_rsi_downcross`、`breadth_15m_transition`。
- `plan.attribution` 写入 `probe_trigger_reason`。
- event_backtest 与 live 使用同一 probe eligibility 函数或同构输入列。

### P2-5 EventBacktest 的验收覆盖仍偏弱
